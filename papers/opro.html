OPRO: Large Language Models as Optimizers

Yang, Wang, Lu, Liu, Le, Zhou, Chen — Google DeepMind·2023baseline
Open PDF (private repo) Back to study plan
Summary

The foundational "LLM-as-optimizer" paper: put the trajectory of past (solution, score) pairs in a prompt, have the LLM propose the next one directly — no explicit surrogate at all. The minimal baseline every other paper here extends or argues against.

Study Notes

The optimization state is written into a meta-prompt

Optimization by PROmpting (OPRO) gives an LLM a natural-language problem description plus earlier candidate solutions and their objective values. The model proposes new candidates, an external evaluator scores them, and the scored candidates return to the next prompt. There is no fitted probabilistic surrogate or explicit uncertainty estimate. The language model itself acts as the proposal mechanism.

OPRO is deliberately a simple iterative baseline

The method sorts prior solutions by score and instructs the optimizer LLM to produce something different and better. Multiple candidates per step improve stability. This uses the model's pattern recognition and domain knowledge without training or gradients, but context length limits how much search history it can retain.

The mathematical examples test mechanism, not state-of-the-art optimization

On small linear-regression and traveling-salesperson instances, stronger LLMs can infer useful update patterns and sometimes match hand-designed heuristics. The authors explicitly state that OPRO is not intended to beat gradient methods on continuous optimization or specialized solvers on classical combinatorial problems. These experiments show that scores in context can steer generation.

Prompt optimization is the main application

The decision variable is a natural-language instruction and the objective is task accuracy on a small training set. This is a search space where an LLM has a meaningful prior and ordinary numeric BO needs an embedding or kernel. OPRO finds prompts that improve over human baselines by up to 8 percentage points on GSM8K and up to 50 points on some Big-Bench Hard tasks.

The memorable prompt is evidence and a warning

For PaLM 2-L on GSM8K, "Take a deep breath and work on this problem step-by-step" reaches 80.2% test accuracy versus 71.8% for "Let's think step by step." Different optimizer and scorer models favor different styles. This demonstrates real prompt sensitivity, but it does not reveal a stable causal reason that the wording works.

Generalization is checked, but selection bias remains a concern

Optimized instructions transfer to held-out examples, other math benchmarks, and in some cases other scorer models. The paper also studies prompt overfitting and meta-prompt ablations. Still, repeated evaluation on small task samples can favor accidental wording, and the method lacks calibrated uncertainty or a principled exploration rule.

Discussion, Section by Section

Plain-English walkthrough (start here)

OPRO replaces a numeric acquisition function with a conversation. Show the model what has been tried and how each trial scored, then ask it to propose a better one.

1. Language is both the interface and the prior

A prompt is hard to search with ordinary geometry. An LLM already knows that some phrasings are related and can compose new ones. OPRO uses that learned intuition as its search bias.

2. The score closes the loop

The LLM does not get to declare success. A separate evaluator assigns the objective value, and only that measured score enters the history. This external check is the method's main guardrail.

3. There is no honest measure of "where we do not know"

Classical BO separates predicted value from uncertainty. OPRO has neither quantity explicitly. It may generate diverse options, but diversity is not the same as calibrated exploration.

Going deeper: the baseline for LLM-augmented BO

The next papers ask how to keep the LLM's semantic prior while restoring pieces of the BO machinery. LLAMBO assigns LLMs specific BO roles. LABO accelerates a surrogate-guided loop. Sara lets an agent control an explicit probabilistic backend. OPRO is the clean comparison point: maximum linguistic flexibility, minimum uncertainty structure.
