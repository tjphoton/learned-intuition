Amortized Bayesian Mixture Models

Kucharský, Bürkner·2025
Open PDF (private repo) Back to study plan
Summary

A worked ABI-workflow example on finite mixture models (label-switching, high-dim posteriors) — a gentler second exercise before metabeta-level hierarchy.

Study Notes

The problem this paper solves: ABI hadn't been extended to categorical latents

Mixture models are hard for classical Bayesian methods for three compounding reasons: full joint inference over parameters and mixture memberships is computationally demanding; MCMC requires an analytically tractable likelihood per component; and the likelihood is invariant to permuting the mixture labels ("label switching"), so the model is only identified up to a relabeling. Amortized Bayesian Inference sidesteps the first two problems, but — as of this paper — had mainly been developed for continuous quantities. Mixture membership indicators are categorical. This paper is the extension that closes that specific gap.

The key move: factorize, then use two different network types for two different jobs

p(θ, {zᵢ} | {yᵢ}) = p(θ | {yᵢ}) · p({zᵢ} | {yᵢ}, θ) — first estimate the continuous parameter posterior with an ordinary amortized posterior network (mixture indicators marginalized out, same trick classical MCMC tools like Stan already use for discrete parameters), then estimate mixture membership with a separate classification network conditioned on both the data and the sampled parameters. Posterior network → normalizing flow (continuous target); classification network → MLP with softmax output (categorical target, essentially soft classification rather than hard labels). The two are trained jointly, sharing summary networks, with a combined loss (Eq. 20).

The paper explicitly considered — and rejected — the mathematically equivalent alternative factorization (classify first, then condition the parameter posterior on the classification). Two concrete, non-arbitrary reasons: most real applications need classification probabilities, not sampled categorical realizations, so nothing is lost by not sampling {zᵢ} first under the chosen factorization; and the alternative would require training two separate global summary networks instead of sharing one.

Local + global summary networks — the same nested pattern as metabeta, applied to a different problem

A local summary network compresses each observational unit's own data into a fixed-size embedding (Deep Sets, for exchangeable within-unit data); a global summary network aggregates those local embeddings for parameter-posterior inference. This is structurally identical to metabeta's local/global summary split — same nested-permutation-invariance idea, applied here to mixture membership rather than hierarchical random effects.

Extending beyond simple mixtures: dependent latents via filtering and smoothing

For exchangeable data (independent mixture components, Fig. 1a), the joint distribution of indicators factorizes trivially per-unit. For dependent latents — e.g. a Hidden Markov Model, where each zₜ depends on the previous state — the paper uses "local decoding": approximate each indicator's distribution one at a time rather than modeling the full joint. Filtering conditions each zₜ only on observations up to time t (via a forward network — an RNN/LSTM, capturing temporal dependency); smoothing additionally conditions on all future observations too, by combining a forward network with a separately-run backward network processing the reversed sequence. The forward and backward networks can share weights when justified (both solve the same kind of subproblem), which the paper notes as a practical efficiency option.

Validation methodology — a rigorous, reusable template

Every case study runs the same battery: simulation-based calibration (SBC, via fractional-rank ECDF plots); parameter-recovery scatter plots (R², correlation); posterior predictive checks; and — genuinely notable — misspecification detection via Maximum Mean Discrepancy (MMD) between real and simulated data, made possible by an MMD regularization loss during training that pushes the summary-network embeddings toward a Gaussian distribution specifically so this test is usable later. This is the exact technique BayesFlow 2 names in its own misspecification-detection section (Schmitt, Bürkner, Köthe & Radev's approach) — implemented here, not just described. Direct comparison to gold-standard MCMC (Stan) via the classifier two-sample test (C2ST, 0.5 = statistically indistinguishable) is used throughout.

Case study results, with real numbers

  • Case Study 1 — independent Gaussian mixture (K=3): SBC showed no clear miscalibration. Parameter recovery R² ranged 0.71–0.79 for mixture weights and 0.82–0.98 for component means. Speed: ~12 seconds total for 500 datasets × 1,000 posterior samples each on BayesFlow (no GPU), versus Stan's ~3 seconds per dataset — roughly a day of compute for the same 500 datasets — about two orders of magnitude faster. C2ST = 0.53, essentially indistinguishable from MCMC. One honest, specific limitation: the neural classifier's membership probabilities were visibly "jittery" compared to MCMC's smooth analytic classification, attributed to the deep ReLU classification network's known tendency toward non-smooth output.
  • Case Study 2 — Gaussian Hidden Markov Model (K=2 states): uses an LSTM (not Deep Sets) as the global summary network specifically because the data now has genuine temporal structure — a direct, concrete instance of "architecture must match data structure." Also ~2 orders of magnitude faster than Stan. SBC showed no clear miscalibration for means or transition probabilities overall — but a real, mechanistically-explained failure mode emerged: parameter recovery for the transition probabilities goes negative (R² = −0.008, −0.088) specifically when the two hidden states are insufficiently separated (μ₂ − μ₁ < 2/3), while recovering well (R² = 0.83–0.84) when states are well separated. The paper's own explanation: poor separation between components increases uncertainty in the mixture indicators themselves, which propagates into reduced precision for anything built on top of them (transition probabilities) — "characteristic of mixture models" generally, not a bug specific to this method. C2ST = 0.56; forward filtering, backward filtering, and smoothing all agreed closely with MCMC.
  • Case Study 3 — real human behavioral data (Dutilh, Wagenmakers, Visser & van der Maas, 2011): models people switching between a fast "guessing" mode (simple evidence-accumulation, shifted-Wald response times) and a slower "controlled" mode (a four-parameter Racing Diffusion Model with two competing accumulators) as a hidden Markov process, fit to genuine speeded decision-making data — a substantive real-world validation, not another synthetic toy.
Discussion, Section by Section

Plain-English walkthrough (start here)

Builds on metabeta's local/global summary networks and BayesFlow 2's misspecification-detection tools — this paper applies both to a genuinely different kind of unknown: not "how big is this effect," but "which of several groups does this data point belong to."

1. Why guessing "which group" is a fundamentally different question than guessing "how much"

Every other amortized-inference paper so far in this module has been estimating numbers on a continuous scale — a slope, a variance, a treatment effect. "Which of these K categories" is a different kind of question entirely, more like sorting mail into bins than reading a dial. That's why this paper needs a second, different kind of network (a classifier) bolted onto the usual posterior-estimating network, rather than just scaling up the same machinery.

2. A subtle trap this paper explicitly avoids: label switching

Imagine fitting three clusters to data and getting back "cluster A, B, C" — but there's nothing in the math forcing the same physical cluster to always be called "A" across different runs. The model genuinely cannot tell "A, B, C" apart from "C, A, B" describing the exact same clusters, just relabeled. That ambiguity breaks naive attempts to average or compare results across runs. The paper handles this by imposing order constraints on the parameters during training (e.g., forcing μ₁ < μ₂ < μ₃) — a standard fix, applied carefully here rather than assumed away.

3. Present, past, and both: three ways to answer "which state was it in"

If you're watching a process unfold over time and it can be in one of a few hidden modes, there are three natural questions: "what mode is it in right now, given everything I've seen so far" (filtering — useful for real-time monitoring), and "what mode was it in at some past moment, now that I've seen everything that happened after too" (smoothing — more accurate, but only possible in hindsight). The paper builds both, using a network that reads forward in time and, for smoothing, a second network that reads the same sequence backward and combines the two views.

4. An honest failure mode, explained rather than hidden

When two hidden groups are genuinely hard to tell apart from the data — their averages are close together — the model has every reason to be uncertain which group any given point belongs to, and that uncertainty doesn't stay contained: it bleeds into every downstream estimate built on top of the group assignments, like transition probabilities between states. The paper doesn't just report this as a mysterious quirk; it explains exactly why it happens and confirms the pattern reverses once the groups are made easier to distinguish. That kind of diagnosed, explained limitation is worth more than a method that never reports failure cases at all.

Going deeper (revisit once the basics above feel solid)

Worth explicit comparison to metabeta once both are fresh: both papers build bespoke, hand-crafted architectures on top of BayesFlow's building blocks to solve one specific structural problem (hierarchical regression vs. mixture membership), both validate rigorously against MCMC via C2ST, and both report roughly two-orders-of-magnitude speedups over their respective MCMC baselines. Together they're the clearest evidence in this library that the "amortized inference beats MCMC by ~100x, with comparable accuracy" pattern isn't specific to one problem type — it shows up again, independently, on a structurally unrelated problem.
